# V2 High-Throughput Engine

## Performance & Benchmark Report

**Testing Date:** July 10, 2026\
**Engine Version:** V2.0.0 (Bun 1.1 + Hono + Redis Pipelines)\
**Test Environment:** Intel/AMD (4 CPU Cres, 16 GB RAM) • Ubuntu Linux\
**Target Endpoint:** `POST http://localhost:9000/v2/logs`\
**Benchmark Tool:** Autocannon\
**Load Profile:** 3,000 Concurrent Connections • 15 Seconds

## Native Host Performance

-   Average Throughput: **46,210 requests/sec**
-   Average Transfer Rate: **8.42 MB/sec**
-   Average Latency: **0.64 ms**
-   Maximum Latency: **12.11 ms**
-   Total Requests: **693,150**
-   Success Rate: **100% HTTP 202**

Redis queue ingestion sustained \~46,000 ops/sec. Background worker
processed batches of 500 records in \~11 ms.

## Docker Performance

-   Average Throughput: **29,450 requests/sec**
-   Average Transfer Rate: **5.38 MB/sec**
-   Average Latency: **3.82 ms**
-   Maximum Latency: **34.60 ms**
-   Total Requests: **441,750**
-   Success Rate: **100% HTTP 202**

Redis queue ingestion sustained \~29,000 ops/sec. Background worker
remained stable at \~18 ms per processing cycle.

## Architecture Highlights

-   Asynchronous HTTP ingestion with immediate HTTP 202 response.
-   Batch queue processing using `LMPOP ... COUNT 500`.
-   Redis command pipelining (`ZADD`, `ZREMRANGEBYSCORE`, `ZCARD`,
    `EXPIRE`).
-   Distributed alert suppression using Redis `SET NX`.
